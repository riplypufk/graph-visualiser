# Визуализатор зависимостей — этап 1

Минимальное CLI-приложение на Python. На этом этапе оно только загружает YAML,
проверяет пользовательские параметры и печатает их в формате `ключ: значение`.
Получение зависимостей и построение графа пока намеренно не реализованы.

## Требования

- Python 3.10+
- PyYAML

## Установка и запуск

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\\Scripts\\Activate.ps1

pip install -r requirements.txt
python main.py
```

Указать другой файл конфигурации:

```bash
python main.py --config path/to/config.yaml
```

## Параметры `config.yaml`

| Ключ | Тип | Назначение |
|---|---|---|
| `package_name` | строка | Имя анализируемого пакета |
| `repository` | строка | URL репозитория либо путь к файлу тестового репозитория |
| `test_repository_mode` | boolean | `true` — тестовый режим, `false` — URL-режим |
| `package_version` | строка | Версия анализируемого пакета |
| `graph_image_file` | строка | Имя будущего PNG-файла |
| `ascii_tree` | boolean | Включить/выключить вывод ASCII-дерева |

Для тестового режима путь к файлу разрешается относительно каталога, в котором
лежит YAML-конфигурация. Для обычного режима проверяется URL со схемой HTTP(S).
Имя изображения должно быть именем файла с расширением `.png`.

## Обработка ошибок

Проверяются:
- отсутствие/неверный тип YAML-документа, синтаксические ошибки и недоступный файл конфигурации;
- отсутствие обязательных и наличие неизвестных ключей;
- пустое/недопустимое имя пакета;
- пустой источник, некорректный URL или отсутствующий/неверный файл тестового репозитория;
- неверный тип режима тестового репозитория;
- пустая/недопустимая версия;
- некорректное имя PNG-файла;
- неверный тип флага ASCII-дерева.

При ошибке программа печатает понятное сообщение в stderr и завершается с кодом 2.

## Автоматические тесты

```bash
python -m unittest discover -s tests -v
```

Тесты демонстрируют обработку ошибочных значений каждого из шести параметров,
а также отсутствующих и неизвестных ключей.
