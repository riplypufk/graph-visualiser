# Инструмент визуализации графа зависимостей для менеджера пакетов

## Этап 3 — построение транзитивного графа зависимостей

На третьем этапе реализовано построение полного графа зависимостей пакета с учётом транзитивности. Программа получает прямые зависимости пакетов, рекурсивно обходит их и формирует граф зависимостей.

Дополнительно реализована поддержка тестового репозитория, позволяющая проверять работу алгоритма без подключения к интернету.

### Реализовано

- получение информации о пакетах из репозитория Alpine Linux в формате APK;
- загрузка и анализ файла `APKINDEX.tar.gz`;
- поиск пакетов по имени и версии;
- извлечение прямых зависимостей пакетов;
- разрешение зависимостей в конкретные пакеты, включая виртуальные зависимости;
- построение транзитивного графа зависимостей;
- реализация обхода графа алгоритмом BFS с рекурсией;
- обработка циклических зависимостей;
- предотвращение повторной обработки уже посещённых пакетов;
- поддержка тестового репозитория с пакетами, обозначенными большими латинскими буквами;
- проверка корректности тестового репозитория;
- вывод построенного графа зависимостей в консоль;
- обработка ошибок при получении и анализе зависимостей.

Для получения информации о зависимостях не используются готовые менеджеры пакетов и сторонние библиотеки.

## Конфигурация

Параметры программы задаются в файле `config.yaml`.

Пример конфигурации для работы с реальным репозиторием:

```yaml
package_name: curl
repository: https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
test_repository_mode: false
package_version: "8.14.1-r2"
graph_image_file: dependencies.png
ascii_tree: true
```

Основные параметры:

| Параметр | Назначение |
|---|---|
| `package_name` | Имя анализируемого пакета |
| `repository` | URL репозитория Alpine Linux или путь к тестовому файлу |
| `test_repository_mode` | Режим работы с тестовым репозиторием |
| `package_version` | Требуемая версия пакета |
| `graph_image_file` | Имя файла изображения графа |
| `ascii_tree` | Режим вывода ASCII-дерева |

Для получения зависимостей из интернет-репозитория параметр `test_repository_mode` должен иметь значение `false`.

Для работы с локальным тестовым репозиторием необходимо установить значение `true` и указать путь к файлу с описанием зависимостей.

## Запуск

Для запуска проекта используется скрипт `run.sh`.

```bash
./run.sh
```

Скрипт выполняет два последовательных действия:

1. Запускает автоматические тесты.
2. Если все тесты успешно пройдены, запускает основную программу.

Используемые команды:

```bash
python3.10 -m unittest discover -s tests -v
```

и:

```bash
python3.10 -m src.main --config config.yaml
```

Если хотя бы один тест завершится с ошибкой, запуск основной программы не выполняется.

## Построение графа зависимостей

Для построения транзитивного графа используется алгоритм поиска в ширину (BFS) с рекурсией.

Алгоритм выполняет следующие действия:

1. Получает прямые зависимости исходного пакета.
2. Добавляет найденные пакеты в граф.
3. Последовательно обрабатывает зависимости каждого найденного пакета.
4. Получает зависимости следующих уровней.
5. Продолжает обход, пока не будут обработаны все доступные зависимости.
6. Использует множество посещённых вершин для предотвращения повторной обработки пакетов.

Каждая вершина графа соответствует отдельному пакету, а направленное ребро обозначает зависимость одного пакета от другого.

Если пакет не имеет собственных зависимостей, он остаётся вершиной без исходящих рёбер.

### Обработка циклических зависимостей

Для предотвращения бесконечного обхода используется множество посещённых пакетов.

Если в процессе обхода обнаруживается пакет, который уже был обработан, повторный обход его зависимостей не выполняется.

Таким образом, программа корректно обрабатывает циклы и общие зависимости нескольких пакетов.

## Тестовый репозиторий

В третьем этапе реализован отдельный режим тестирования, который позволяет строить граф зависимостей без обращения к интернет-репозиториям.

В тестовом репозитории пакеты обозначаются большими латинскими буквами.

Пример конфигурации:

```yaml
package_name: A
repository: tests/data/looped_repository.txt
test_repository_mode: true
package_version: "1"
graph_image_file: dependencies.png
ascii_tree: false
```

Пример содержимого файла `looped_repository.txt`:

```text
A: B C
B: D
C: D
D: E
E: A
```

В тестовом файле каждая строка описывает пакет и его прямые зависимости.

Поддерживаются два варианта разделителей:

```text
A: B C
```

и:

```text
A -> B C
```

Тестовый репозиторий позволяет проверять:

- последовательные цепочки зависимостей;
- ветвления графа;
- общие зависимости нескольких пакетов;
- циклические зависимости;
- пакеты без собственных зависимостей;
- обработку отсутствующих пакетов;
- обработку некорректных записей.

Тестовый режим полностью исключает необходимость загрузки APKINDEX из интернета.

## Результат работы

Пример результата построения графа для пакета `curl`:

```text
Граф зависимостей:
curl -> libcurl musl zlib
libcurl -> ca-certificates brotli-libs musl c-ares libcrypto3 libidn2 nghttp2-libs libpsl libssl3 zlib zstd-libs
musl ->
zlib -> musl
ca-certificates -> musl libcrypto3
brotli-libs -> musl
c-ares -> musl
libcrypto3 -> musl
libidn2 -> musl libunistring
nghttp2-libs -> musl
libpsl -> musl libidn2 libunistring
libssl3 -> libcrypto3 musl
zstd-libs -> musl
libunistring -> musl
```

Пример результата для тестового репозитория с циклической зависимостью:

```text
Граф зависимостей:
A -> B C
B -> D
C -> D
D -> E
E -> A
```

В данном примере:

- пакет `A` имеет две прямые зависимости: `B` и `C`;
- пакеты `B` и `C` имеют общую зависимость `D`;
- пакет `D` зависит от `E`;
- пакет `E` зависит от исходного пакета `A`, образуя цикл.

Программа корректно строит граф и завершает обход без бесконечной рекурсии.

## Тестирование

Для проекта реализованы автоматические тесты, проверяющие корректность работы конфигурации, получения зависимостей и построения графа.

Проверяются следующие случаи:

- разбор прямых зависимостей;
- обработка пустого списка зависимостей;
- разбор `APKINDEX`;
- извлечение `APKINDEX` из архива;
- поиск пакета по имени и версии;
- обработка неизвестного пакета;
- проверка конфигурации;
- чтение тестового репозитория;
- проверка корректности записей тестового репозитория;
- построение транзитивного графа;
- обработка общих зависимостей;
- обработка циклических зависимостей;
- обработка пакетов без зависимостей.

Проверка выполняется автоматически при запуске:

```bash
./run.sh
```

Успешное прохождение тестов позволяет запустить основную программу.

- `run.sh` — автоматический запуск тестов и основной программы;
- `README.md` — документация проекта.

## Результат этапа 3

На третьем этапе реализовано построение транзитивного графа зависимостей пакетов.

Программа получает зависимости исходного пакета, рекурсивно обходит найденные пакеты с использованием алгоритма BFS и формирует полный граф зависимостей.

Реализована обработка циклических зависимостей, повторно встречающихся пакетов и общих зависимостей.

Дополнительно реализован тестовый режим, позволяющий проверять алгоритм на специально подготовленных репозиториях без обращения к интернету.
